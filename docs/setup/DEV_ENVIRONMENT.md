## Emulator `tower_phone`

Run `C:\dev\tower\tools\run_emulator.ps1` (add `-ColdBoot` to skip the quickboot snapshot).
Boot takes ~30-55 s. After a cold boot wait ~20 s before launching apps (see Troubleshooting).

config.ini values (edited by hand, see Troubleshooting):

```
hw.device.name=pixel_6          hw.lcd.width=1080  hw.lcd.height=2400  hw.lcd.density=420
hw.initialOrientation=portrait  hw.ramSize=2560    vm.heapSize=256
hw.cpu.ncore=3                  hw.gpu.enabled=yes hw.gpu.mode=host
PlayStore.enabled=yes           tag.id=google_apis_playstore
disk.dataPartition.size=6G      fastboot.forceFastBoot=yes  fastboot.forceColdBoot=no
image.sysdir.1=system-images\android-35\google_apis_playstore\x86_64\
```

Accelerator: WHPX (the "Please disable Hyper-V" warning from `emulator -accel-check` is bogus; ignore it).
The script starts the emulator with `-gpu host -no-boot-anim -no-audio`.

Stop it: `adb emu kill`.

## Export, install, launch from the command line

One command (emulator or phone must be online):

```powershell
C:\dev\tower\tools\deploy_android.ps1 -ProjectPath C:\dev\tower -Package com.yourco.tower   # -Preset "Android" default
```

It runs `godot --headless --import`, `--export-debug "Android" build\<package>.debug.apk`, `adb install -r`,
launches via monkey, prints Godot-tag logcat for `-LogSeconds` (default 8; the first run needs ~30 s because
of shader compilation on the emulator), and reports whether the process is running.

Manual equivalent:

```powershell
$g = "C:\dev\tools\godot\4.7.2\Godot_v4.7.2-stable_win64_console.exe"
& $g --headless --path <proj> --export-debug "Android" <out.apk>
adb install -r <out.apk>
adb shell monkey -p <package> -c android.intent.category.LAUNCHER 1
adb logcat -s godot:V
adb exec-out screencap -p > shot.png     # use cmd.exe from a local drive, not a \\wsl$ path
```

The project needs an Android export preset (`export_presets.cfg`) and a project icon (`application/config/icon`);
the smoke test project at `C:\dev\tools\smoke_test` is a working template (Compatibility renderer,
portrait 720x1280, arm64-v8a + x86_64, no Gradle build). Note the smoke test sets `screen/immersive_mode=true`,
which shows a one-time "Viewing full screen" system dialog on a fresh emulator (tap "Got it").
For Gradle builds (plugins such as AdMob / Play Billing) set `gradle_build/use_gradle_build=true` and run
"Install Android Build Template" once from the editor; the NDK/CMake/build-tools above are already in place.

## Physical phone (lighter alternative)

USB: enable Developer options, USB debugging; plug in; accept the RSA prompt; `adb devices`.
Then run `deploy_android.ps1 ... -Serial <serial from adb devices>` (needed if the emulator is also running).

Wi-Fi (Android 11+): Developer options, Wireless debugging, "Pair device with pairing code";
`adb pair <ip>:<pairport>` (enter code), then `adb connect <ip>:<port>`. Same Wi-Fi network required.
Godot's one-click deploy button also works with these devices. Phones have real GPUs, so performance is far
better than the emulator on this laptop.

## Troubleshooting

- **"Please disable Hyper-V" in `emulator -accel-check`**: ignore. WHPX is the correct accelerator, and WSL2 needs Hyper-V. Do not touch `bcdedit`.
- **Java 11 vs 17**: system `java` is 11; Godot 4 export needs 17. Godot uses `java_sdk_path` from editor settings.
  For sdkmanager/avdmanager set `$env:JAVA_HOME='C:\dev\tools\jdk-17'` in that PowerShell session only.
  Godot autodetected the Java 11 path at first run; it was overwritten in `editor_settings-4.7.tres`.
- **sdkmanager --licenses with piped `y` does nothing in PowerShell**: use `cmd /c "sdkmanager.bat --sdk_root=... --licenses < yes.txt"` with a file of `y` lines.
- **`avdmanager create avd` printed "Could not load devices ... devices.xml"** for this system image and left a template config
  (`avd.id=<build>`, PlayStore off). The AVD folder was created, so `config.ini` was fixed by hand to the values above.
  The emulator rewrites config.ini with `key = value` spacing; when scripting edits, match `\s*=\s*`.
- **Godot: "Could not find version of build tools that matches Target SDK"**: install `build-tools;36.0.0`
  (Godot 4.7 targets SDK 36 even though the docs list 35.0.1).
- **Godot: "No project icon specified"**: set Project Settings, Application, Config, Icon (even a simple SVG).
- **Godot parse error `res://main.tscn:1 - Expected '['`**: file had a UTF-8 BOM (Windows PowerShell 5.1 `Set-Content -Encoding utf8`). Write project files without BOM.
- **After export, `adb: device offline` / "daemon not running"**: Godot restarts the adb server; run `adb start-server`
  and wait for `adb get-state` to print `device` (the deploy script does this).
- **Emulator black or blank render, log says `Fragment shader active uniforms exceed GL_MAX_FRAGMENT_UNIFORM_VECTORS (261)`**:
  with `-gpu auto` the guest GL driver had too few uniform vectors and Godot's canvas shader failed to link
  (only the clear colour showed). Use `hw.gpu.mode=host` (Intel Iris here), which reports a full GL ES 3.0 translator.
  Fallbacks: `-gpu swangle_indirect` or `-gpu swiftshader_indirect` (slow but compatible).
- **App killed ~10 s after launching right after a cold boot** (activity destroyed, "Force quitting Godot instance"):
  Play Store/Play Services update activity right after first boot. Wait ~20-30 s after a cold boot, then launch again.
- **App shows black for ~30 s on first launch** with host GPU: shader compile; later launches use the cache.
- **Emulator performance on this laptop (4 cores, 15.7 GB, Iris Plus)**: keep 2.5 GB RAM and 3 cores, keep quickboot on
  (`-ColdBoot` only when needed), use `-no-audio`, close Android Studio and heavy WSL workloads while it runs,
  prefer a physical phone for performance-sensitive testing, and kill it (`adb emu kill`) when done.
  Quickboot snapshots occupy ~2 GB of disk under the AVD folder.
- **`adb exec-out screencap -p > file` from a `\\wsl.localhost` working directory**: cmd.exe refuses UNC paths; run it from `C:\`.
- **Ads never load (code 2, `ERR_CONNECTION_REFUSED`) or consent update fails**: the host DNS can resolve ad domains
  (e.g. `googleads.g.doubleclick.net`) to 127.0.0.1. Start the emulator with `.\tools\run_emulator.ps1 -PublicDns`
  (passes `-dns-server 8.8.8.8,1.1.1.1`). Opt-in only: the DNS filtering may be deliberate. It takes effect only on a
  fresh emulator start (`adb emu kill` first).
- **adb shows the emulator "offline" after a warm boot**: `adb emu kill`, then `.\tools\run_emulator.ps1 -ColdBoot`.
