## Goal

- **Sim stays pure and deterministic.** Wave mode and patches change sim outcomes: `SimVersion.CURRENT` goes 2 to 3 in M4-04 (wave modes) and 3 to 4 in M4-15 (patches). - **Where things live:** `src/meta/modes/` (new, pure) for `ModeRules`; `src/data_defs/wave_mode_def.gd`; sim code in `src/sim/`; UI in `src/ui/home/`, `src/ui/` (results, HUD), new `src/ui/draft/`, `src/ui/intel/`, `src/view/` for damage numbers, `src/core/haptics.gd` glue (Input vibration is a node-layer call, never in `src/sim` or `src/meta`).

## M4-03 Deterministic PURGE wave-end rule
- **Status:** [x] 2026-11-09
- **Goal:** in PURGE a wave ends when its quota is destroyed, or at the backstop.
- **Size:** L. **Depends on:** M4-02.
- **Files:** `src/sim/sim_world.gd` (the wave clock branch in `step()`), `src/sim/systems/wave_end_system.gd` (unchanged order, may gain a `reason` argument), new `src/sim/systems/purge_clock.gd` (`PurgeClock.wave_done(world) -> bool`), `src/sim/sim_event_kind.gd` (new `WAVE_PURGED` event, a = wave, b = ticks used), `src/sim/wave_plan_state.gd` (a `remaining_unspawned()` helper), `src/sim/entities/enemy_store.gd` (read only: `born_wave`), `tests/unit/sim/test_purge_clock.gd`, `tests/unit/sim/test_sim_world.gd` (extend).
- **Spec (Q72, Q73):**
  - TIMED code path is untouched: `wave_tick >= Ticks.WAVE_TICKS` ends the wave.
  - PURGE: a wave is done when (a) every plan entry that is not carried is spawned, (b) every enemy with `born_wave == wave` is dead (boss included), or (c) `wave_tick >= config.purge_backstop_ticks`. On done: run `WaveEndSystem.step`, `wave += 1`, `wave_tick = 0`, push `WAVE_STARTED` as today. No lull: spawn phase continues to use `wave_tick` as now, the wave simply ends sooner.
  - Carry-over: on backstop expiry unspawned entries carry into the next plan and living enemies stay (same `plan.begin(wave, true)` rule as TIMED). In PURGE a wave that ends by clearing has nothing to carry.
  - Evaluation happens once per tick after `ProjectileSystem` and `ExposureSystem` (same place as the TIMED check) and uses only integer state, so speed 1x/2x/4x give identical hashes.
  - `WAVE_ENDED` stays the first event of `WaveEndSystem`; `WAVE_PURGED` is pushed before it only when the wave ended by clearing. The stale rule (3 wave ends) and `level_hp/level_atk` increments are unchanged per wave end.
- **Acceptance:** unit tests with a hand-built world: (1) a wave whose enemies are all killed at tick 400 ends at tick 400 and the next wave starts next tick; (2) one enemy kept alive (invulnerable stub) ends the wave exactly at `purge_backstop_ticks` and its enemy survives into wave+1; (3) entries blocked by the alive caps keep the wave open until they spawn and die; (4) a boss wave ends only after the boss is dead; (5) TIMED world with the same scenario still ends at tick 720 and its state hash equals the pre-change hash (run before and after, quote both); (6) a PURGE run to wave 15 gives the same final hash stepped at 1 tick/frame and 4 ticks/frame; lint clean.
