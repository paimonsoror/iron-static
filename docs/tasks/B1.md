# B1 Play open beta - agent task file

Changelog: v1.0 2026-11-09 (planning, branch `b1-plan`). Milestone goal, scope and exit criteria: `docs/ROADMAP.md` section B1. The user's step-by-step guide: `docs/release/PLAY_BETA_GUIDE.md`. Verified Google requirements and sources: `docs/release/research_2026-11.md`. 12 tasks: build and compliance (B1-01 to B1-04), store material (B1-05, B1-06, B1-08, B1-09), verification (B1-07), user-run Play Console tracks (B1-10 to B1-12).

## Goal

A signed Android App Bundle of the current MVP build that Google Play accepts, that sends no data and contains no ads, billing or crash-reporting SDK, listed in an open test that anyone can join, with a privacy policy, store graphics, a feedback path and a record of every declaration made.

## Scope

- Beta build only: no ads, no purchases, no accounts, no analytics, no network use (decision defaults Q79-Q86 in `docs/design/09_open_questions.md`). Plugins for those arrive again in M7 with their own Data safety update.
- Tooling and documents. No gameplay, sim, balance or save-format change. The only runtime code change is the Settings "About" additions in B1-08.
- Tasks marked **USER** need the user at the keyboard (Play Console, keystore, approvals). Agents never type secrets, never commit keystores, never publish to Play.

## Rules that apply to every task

- `export_presets.cfg` and `project.godot` are shared files: these tasks own the named edits only (B1-01 the new preset and signing options, B1-03 the SDK options, B1-04 plugin and permission options, B1-02 the version fields). Do not touch the existing debug preset `IronStatic` except where a task says so; the emulator deploy flow (`tools\deploy_android.ps1 -Preset IronStatic`) must keep working.
- Secrets: release keystore, its passwords and any real id come only from the ignored `secrets.local.json` or environment variables. `git status` must never show a `.jks`, `.keystore`, `.aab`, password or the file `secrets.local.json`.
- Docs under `docs/setup/` may be edited by these tasks where a task names them. Add a one-line note to `docs/setup/plugin_matrix.md` for the plugin decisions (CLAUDE.md rule).
- Definition of done as in CLAUDE.md (lint, tests, debug APK still installs). Release artifacts are checked with the commands in each task; paste outputs into the commit message or the task notes.
- Never write franchise names (CLAUDE.md IP rules) in store text, privacy text or graphics. Do not put the user's email address in any file.

## Exit criteria

1. `tools\release_build.ps1` produces `build/release/ironstatic-<versionName>.aab` signed with the upload key, from a clean checkout plus the user's `secrets.local.json`.
2. The AAB's merged manifest: `targetSdkVersion` 36, `minSdkVersion` 24, only the VIBRATE permission (INTERNET decided in B1-04), no `AD_ID`, no `BILLING`, no ads or Sentry components; `bundletool dump config` says `PAGE_ALIGNMENT_16K`; every `.so` for arm64-v8a and x86_64 passes the 16 KB check.
3. The exact AAB installs (via `bundletool build-apks --mode=universal`) on the emulator and the user's phone, passes `smoke_android.ps1`, and runs a full run to Results and back with no error lines.
4. Privacy policy page is live on the codex; store graphics meet Play's size rules; the declaration answers are recorded in the repo and match the build.
5. **USER:** internal test installed from Play and the pre-launch report reviewed; closed test run if the account needs it and production access granted; open test live and the opt-in link installed from a clean phone.

## B1-01 Release preset, AAB export, release signing and build script
- **Status:** [ ]
- **Goal:** one command builds a signed beta AAB without secrets in git.
- **Size:** L. **Depends on:** none. **Needs the user:** yes (create the upload keystore; guide phase 2) - the agent can finish and test everything except the signed export until `secrets.local.json` has the keystore fields. Until then test with the Godot debug key and report "release signing untested".
- **Files:** `export_presets.cfg` (new preset `IronStaticBeta`, preset.1; keep preset.0 unchanged), `tools/release_build.ps1`, `tools/_common.ps1` (small helper to read `secrets.local.json` only if the existing helpers do not already), `docs/setup/android_export.md` (new section "Release AAB"), `docs/release/signing.md` (new; how the key works, backup rules, reset procedure), `.gitignore` (add `/release/private/` only if the task needs a local folder), `secrets.local.json.example` (new, tracked, with empty placeholder fields).
- **Spec:**
  1. Preset `IronStaticBeta`: Android, runnable false, `gradle_build/use_gradle_build=true`, `gradle_build/export_format=1` (AAB), `export_path="build/release/ironstatic-beta.aab"` (the script renames to the versioned name), architectures arm64-v8a and x86_64 on (x86_64 is needed to run the exact bundle on the emulator; Q35 keeps armeabi-v7a off), `package/signed=true`, same `exclude_filter` as the debug preset plus anything B1-04 adds, `package/unique_name` and `package/name` identical to preset 0, `screen/immersive_mode` identical, `user_data_backup/allow=false`, `package/retain_data_on_uninstall=false`.
  2. No keystore path or password in `export_presets.cfg`. `release_build.ps1` reads `secrets.local.json` fields `android_release_keystore_path`, `android_release_keystore_user`, `android_release_keystore_password` and sets the process-level environment variables `GODOT_ANDROID_KEYSTORE_RELEASE_PATH`, `_USER`, `_PASSWORD` (Godot docs: they override the preset; key and keystore passwords must be equal) only for the child Godot process. It fails with a clear message if a field is missing, if the keystore file does not exist, or if the file is inside the repo working tree.
  3. The script: checks `git status` is clean except ignored files (or `-AllowDirty` with a loud warning), runs `tools\setup_android_template.ps1` if the Gradle template is missing, imports, then `godot --headless --export-release IronStaticBeta` through the existing `Invoke-GodotRetry`, **verifies the output exists and is newer than the start time** (headless Godot can exit 0 on failure), copies to `build/release/ironstatic-<versionName>-<versionCode>.aab`, writes `.sha256`, prints size and the signer certificate SHA-1 and SHA-256 (`keytool -printcert -jarfile`), and refuses to proceed if the bundle is signed with the Android debug certificate (CN=Android Debug).
  4. Gradle uses `org.gradle.daemon=false` (existing gotcha). Build runs from `C:\dev\tower` style local path, never `\\wsl$`.
  5. The release build is not a debug build: no `--debug-perf` flags, `Export With Debug` off. Record the AAB size; if above 150 MB flag it in the notes (Play size limits not verified in research; B1-04 should shrink it).
- **Acceptance:** `release_build.ps1` run twice (with the user's key if present) gives an AAB each time; `jarsigner -verify -verbose -certs` shows the upload certificate and not the debug one; `git status` shows no secret, key or AAB; the script exits non-zero with a readable error when (a) a field is missing, (b) the keystore is inside the repo, (c) the export produced no new file (canary: temporarily point at a bad preset name); debug deploy to the emulator still works; notes list the AAB size in MB and the SHA-1 of the upload certificate (the user pastes it nowhere; it is for Play Console only if they ever use Play Games or sign-in).

## B1-02 Version scheme and single source of truth
- **Status:** [ ]
- **Goal:** one file defines the version; the preset, project settings and in-game label always agree.
- **Size:** S. **Depends on:** none (B1-01 consumes it). **Needs the user:** no.
- **Files:** `release/version.json` (new; `{"major":0,"minor":5,"patch":0,"stage":"beta","build":1}`), `tools/release_version.ps1` (`-Show`, `-Bump build|patch|minor|major`, `-Apply`), `export_presets.cfg` (only `version/code` and `version/name` of both presets, written by the tool), `project.godot` (`config/version`), `src/core/game.gd` (the `VERSION` constant: read where it is defined today and make it read from the generated file or the project setting; keep one source), `tests/unit/core/test_version.gd`, `docs/release/versioning.md` (short).
- **Spec:** `versionName` = `MAJOR.MINOR.PATCH` plus `-beta.BUILD` while `stage` is `beta` (e.g. `0.5.0-beta.1`); at launch the stage becomes empty and the name is plain. `versionCode` = `MAJOR*1000000 + MINOR*10000 + PATCH*100 + BUILD` (BUILD 1-99; e.g. 50001); Play requires a code higher than every code ever uploaded and at most 2,100,000,000; the tool refuses to lower the code or exceed BUILD 99. `-Apply` rewrites the preset values and `config/version` idempotently and keeps LF line endings and UTF-8 without BOM. `release_build.ps1` calls `-Apply` and aborts if the git tree then differs from HEAD unexpectedly (it prints a diff of version fields). The in-game text (Settings, title screen if it shows one) shows the same string as the AAB.
- **Acceptance:** unit test: parsing `version.json` gives name `0.5.0-beta.1` and code 50001; bumping build gives 50002; lowering is refused; after `-Apply`, `grep` of `export_presets.cfg` and `project.godot` shows the same strings and code; the in-game `Game.VERSION` equals the preset `version/name` (test reads both); lint and tests pass.

## B1-03 Target SDK 36, 16 KB page size and manifest audit
- **Status:** [ ]
- **Goal:** the bundle meets Play's target API and 16 KB rules and has no surprise manifest entries.
- **Size:** M. **Depends on:** B1-01. **Needs the user:** no.
- **Files:** `export_presets.cfg` (`gradle_build/target_sdk="36"`, `gradle_build/min_sdk="24"` on the beta preset; keep the debug preset as is), `tools/aab_check.ps1` (new: runs bundletool and the 16 KB and manifest checks, exit 0 PASS / 1 FAIL / 2 error), `docs/setup/DEV_ENVIRONMENT.md` (bundletool and Build-Tools install lines), `docs/release/aab_audit.md` (the recorded result), `tools/bundletool_version.txt` (pin).
- **Spec:**
  1. Set `target_sdk` explicitly to 36 (Play requires 36 for new apps and updates since 2026-08-31; the empty default currently resolves to 36 in Godot 4.7 but a pin avoids drift). `compileSdk` follows the template.
  2. `aab_check.ps1` takes an AAB path and: (a) `bundletool dump manifest` and asserts `android:targetSdkVersion="36"`, `minSdkVersion="24"`, the permission list equals the allowed list (default: `android.permission.VIBRATE`; `INTERNET` only if B1-04 keeps it), `android:allowBackup="false"`, `android:appCategory` is `game` or the activity/application has the Game category, no `exported="true"` component except the launcher activity; (b) `bundletool dump config` contains `PAGE_ALIGNMENT_16K`; (c) builds a universal APK set, extracts every `lib/arm64-v8a/*.so` and `lib/x86_64/*.so` and checks each LOAD segment alignment is at least 2**14 with the NDK `llvm-objdump -p`, plus `zipalign -c -P 16 -v 4` on the universal APK, and the RELRO rule from the Android page; (d) prints the AAB size and the three biggest files.
  3. Required downloads (pin and document): bundletool jar, Build-Tools 35.0.0 or newer (`zipalign`), NDK r28 `llvm-objdump` (the Godot docs list NDK r28b). Do not run them against the user's phone in this task.
  4. Record Godot 4.7.2's actual behavior in `aab_audit.md`: library list with alignment, any failing `.so` and its owner (engine, GDExtension, plugin AAR).
  5. Android 16 behavior notes to verify on the emulator (API 35 AVD `tower_phone` plus, if available, an API 36 image): edge-to-edge insets (immersive mode, safe areas), predictive back (no crash when swiping back on the title/run screen), game category present so large-screen orientation/resizability limits are not forced (research 2.4). If a 16 KB system image is installable, run the exact AAB on it (`adb shell getconf PAGE_SIZE` = 16384); if not, report "not run".
- **Acceptance:** `aab_check.ps1 build\release\...aab` prints PASS with the numbers above; a deliberately wrong input (the debug APK, or an AAB with `INTERNET` added) makes it FAIL; `aab_audit.md` lists each native library with its alignment; any failing library has a follow-up item (update, remove, or exclude) linked in the task notes; lint and tests pass.

## B1-04 Beta build without billing, ads and crash reporting
- **Status:** [ ]
- **Goal:** the Data safety form can truthfully say "no data collected or shared" and the manifest has no ads or billing leftovers.
- **Size:** L. **Depends on:** B1-01. **Needs the user:** one decision confirmation (Q81, default: no Sentry in the beta).
- **Files:** `export_presets.cfg` (beta preset only: plugin checkboxes off, `permissions/internet` per decision, `exclude_filter` additions), `project.godot` (only if a plugin setting such as the AdMob app id must be cleared for the beta; the debug flow must keep working), `src/services/services.gd` (only if the stub fallback needs a beta guard), `docs/setup/plugin_matrix.md` (decision notes for Billing, AdMob/UMP, Sentry, Nakama in the beta), `docs/release/beta_build_decisions.md`, tests for the service selection.
- **Spec:**
  1. Beta preset turns off: Google Play Billing plugin, AdMob/UMP plugin. `Services` already falls back to `BillingStub`/`AdsStub` when the singleton is absent; add a test that, with no Android singletons, both are stubs and every `Services` call returns "unavailable" without error.
  2. Sentry: **default decision: not in the beta.** Exclude the Sentry GDExtension and its Android plugin from the beta export (preferred: preset `exclude_filter` `addons/sentry/*` plus the plugin checkbox; fallback if the extension still loads or the AAR is still merged: a staging copy of the project made by `release_build.ps1` that deletes `addons/sentry` before export). Remove or guard the `[sentry]` settings so no boot error appears. Crash data then comes from Play vitals and tester feedback. If the user instead chooses to keep Sentry (Q81 alternative), the Data safety form must declare crash logs and diagnostics, the DSN comes from `secrets.local.json`, and B1-09's answer record changes: say so in the notes and stop.
  3. Nakama client: GDScript only, no native code, `backend_offline.gd` is the active backend. Keep the addon in the repo, make sure the beta never constructs a networked client (assert in a unit test that the default `Backend` is the offline one), and exclude `addons/com.heroiclabs.nakama/*` from the beta export to keep it out of the bundle if nothing preloads it.
  4. INTERNET permission: decision default **off** for the beta (nothing needs it; `OS.shell_open` for the feedback link opens the browser without it). Turn `permissions/internet` off in the beta preset, remove other plugin-added permissions (`AD_ID`, `BILLING`, `ACCESS_NETWORK_STATE`, `com.google.android.gms.permission.AD_ID`, `WAKE_LOCK` if only ads need it) by not including the plugins. Keep `VIBRATE` (haptics, M4-22).
  5. Remove ad and billing metadata that Gradle merges (`com.google.android.gms.ads.APPLICATION_ID`, billing activity entries) - verify they are absent, not just the permissions.
  6. Size: report the AAB size before and after; the debug APK with plugins is 170-180 MB (plugin_matrix.md).
  7. Verify the game works without the INTERNET permission: boot, run, results, Foundry, settings, haptics, save and resume.
- **Acceptance:** `aab_check.ps1` (B1-03) permission list is exactly `VIBRATE`; `grep` of the merged manifest (`bundletool dump manifest`) finds none of: `AD_ID`, `BILLING`, `ads.APPLICATION_ID`, `sentry`, `INTERNET`; no `libsentry*.so` in the bundle (`bundletool` or unzip listing); the exact AAB runs on the emulator with `smoke_android.ps1` clean; the debug preset still includes the plugins and the existing `--probe-services` flow works; a test proves the stub selection; plugin_matrix.md has the four decision lines; before/after sizes quoted.

  3. **Phone screenshots** (min 2, produce 6-8): portrait **1080x1920 (9:16)**, JPEG or 24-bit PNG without alpha.   4. **Foldable/tablet screenshots** (optional, recommended for large-screen quality): 4 images at 16:9 landscape or 9:16 portrait between 1,080 and 7,680 px; because the game is portrait-only, make 1080x1920 portrait images of the game in the same window on a tablet-class emulator if one is configured; otherwise skip and note it.

  6. Optionally a 30-90 s promo video (YouTube) is out of scope.
- **Acceptance:** `tools\store_assets.ps1` regenerates everything; the validator prints PASS with the sizes table; `release/store/` holds `icon_512.png`, `feature_1024x500.png`, `phone_01..08.png` (and optional tablet files); the user approves the set (visual check by viewing the files); no file exceeds Play's limits; `docs/release/store_assets.md` documents commands.
