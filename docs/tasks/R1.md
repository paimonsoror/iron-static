# R1 Review follow-up: feel pass - agent task file

Changelog: v1.0 2026-11-10 (planning, from the user's decisions on the independent review).

Source: `docs/review/2026-11_fable_review.md` (finding ids G-xx gameplay, I-xx image, C-xx code, O-xx other; evidence in `docs/review/fable/`). Decisions: `docs/design/09_open_questions.md` Q88-Q90 (2026-11-10).

## Goal

Spend the next stretch on the part of the game a player feels, the ten minutes in the middle of a run, before building more meta. Concretely: choices that matter (drafts), a burn state the player lives in, less dead time, a Foundry that never shows a locked door, and visuals that show the fight. Then check the build on the phone, then add identity mechanics, then reasons to come back.

## User decisions (2026-11-10)

1. **Open test held (Q88).** The B1 open track (B1-12) waits until 5-8 people have played the build on a phone (FC1-FC4, FC7, FC12; screen-recorded, no coaching) and FC4 and FC12 pass. The internal and closed tracks continue.
2. **Foundry soft cap (Q89).** The FO-3 hard cap becomes a soft one: levels above the best-wave limit cost more instead of being locked. Measured with the journey tool before it ships.
3. **Order (Q90).** Phase A quick wins, then Phase B phone checks, then Phase C identity, then Phase D reasons to return. Lab, firmware and backend work stay on hold. No finding was rejected; deferred items are listed at the end.

## Order and parallelism

- Phase A runs as three parallel agents:
  - `R1-SIM` (R1-01, R1-02, R1-05) and `R1-DRAFT` (R1-04) both change the sim. SimVersion goes 5 to 6 once for the whole of Phase A; the coordinator re-records goldens at merge.
  - `R1-FEEL` (R1-03, R1-06, R1-08) does not change sim outcomes.
  - The final journey tune in R1-02 runs after R1-04 and R1-05 are on main, because drafts and the burn change both move balance.
  - R1-07 (text and contrast) runs last, because it touches strings and screens that the other tasks change.
- M4-28 (M4 exit check) and B1-06/B1-07 run after Phase A, so the beta build carries it.
- The human fun checks (O-01) run on the Phase A build. Run them again after Phase C if possible.
- Machine limits: the dev PC has 15.7 GB RAM with about 4-5 GB free. Run one Godot export or Gradle build at a time; no task in Phase A exports. Before every Godot run, check free memory and wait while it is under about 2.5 GB.

### R1-03 Faster game speed with automatic fall-back (G-05 option 2)
- **Status:** [ ]
- **Spec:**
  - **Speeds.** Speeds 1x, 2x, 4x, 8x (`src/ui/hud.gd` `SPEEDS`). 4x unlocks at best TIMED wave 30 and 8x at 60, as data in the same pattern as the other unlocks. The speed button cycles through the unlocked speeds. Locked speeds are not shown; the next unlock appears in the existing unlock chip.
  - **Fall-back.** Above 2x, the effective speed drops to 2x while Cinder's hull is below 75% or a boss is alive. It returns to the chosen speed when hull is at or above 80% and no boss is alive. The HUD shows both values (for example "8x" dimmed with "2x" lit). Same rule in PURGE.
  - **High-speed load.** Throttle what scales with ticks per frame at 4x and 8x: SFX voices per frame, haptics, damage numbers, spark particles. Keep the frame under budget; measure ms per frame at 8x on a late-run state with the existing perf tooling.
  - **Determinism.** Speed only changes ticks per frame. Add a sim test that a seeded run with the same inputs ends with the same state hash at 1x, 2x and 8x (FC11).
  - **Docs.** GDD 02 s14 says 3x and 4x come from Lab at Launch; record the change with a changelog line.
- **Acceptance:** tests for the unlock gates, the fall-back hysteresis, the cycle order and the hash equality; a perf number at 8x; a screenshot of the HUD speed control in fall-back.

### R1-04 Draft rework: earlier, one card per family, a reroll, better cards (G-02 steps 1-2, I-04)
- **Status:** [x] 2026-11-10, branch `r1-draft` (local; numbers in the commit message)
- **Spec:**

  - **Offer.** One ARMS, one CHASSIS and one SYSTEMS card per draft. A patch's family is the family of its `stat` in `data/run_upgrades.csv`; give a multi-stat patch an explicit family column if needed. The gamble roll keeps its share (`draft_mix_gamble`) and replaces the card of the gamble's family. When a family has no eligible patch (all maxed), fill from the others.
  - **Reroll.** One reroll per draft. It is a command in the input log, drawn from the sim RNG so replays hold, and rerolls all three cards.
  - **Cards (I-04).** Each card shows:

    - the patch name
    - the concrete change for this run (e.g. "LASER 28.6 -> 32.9")
    - pick pips (picks held of max)

    A gamble shows its cost on a red-tinted lower half. Add a reroll button that shows whether the reroll is used.
  - **Tutorial.** Check that the FTUE draft hint still fires and reads right at the wave-5 draft.
  - **Docs.** GDD 02 s10 and 07 s2.9 changelog lines; 08 s1.5 if the patch list wording changes.
- **Acceptance:**
  - Unit tests for the schedule, the family slots and their fallback, the gamble replacement, the reroll determinism (replay hash), and the card model numbers.
  - Re-run the review's draft experiment (`docs/review/fable/scripts/rev_exp.gd.txt`, copied to a temp tool and removed again) on the fresh and mid profiles and report the result:

## Phase C: identity (outline)

- **Prototype lane (C-11):** `data/experiments/*.csv` overlay and an experimental flag for debug builds, so a mechanic can be tried on the phone before full gates.
- **Crowd (G-04, I-01, I-02, C-01, C-08):** twice the bodies at equal wave HP, confirmed with the journey tool; then SPLIT LENS (beam forks) and one area effect, then x4-x6 bodies. One-pass buffer fill if the body count makes it matter.
- **Identity verb (G-10):** a protocol chip (NEAREST / RANGED FIRST / HEAVIEST / WEAKEST) and/or tap-to-designate. CHORUS counter-measures every 10 waves.
- **Burn as a played state (G-03 steps 2-4):** burn pays (laser and Data bonus per band), a VENT control, slower repair in melee contact.
- **Rule patches (G-02 step 3):** SPLIT LENS, ARC RETURN, HOT PLATES, RELAY PULSE, CHORUS JAMMER, COLD CORE, OVERWATCH; some replace stat patches.
- **Frames (G-11):** one visible mechanic per frame; best wave per frame and mode; frame gate on mid and late profiles.
- **Voice (G-13):** `data/lines.csv` with run-start, boss, band-change and death lines.
- **Image (I-07, I-09, I-10, I-11):** a status portrait of the standing Cinder in the HUD; amber reserved for values and the primary action; one banner lane; a camera fit cap with an edge indicator.
