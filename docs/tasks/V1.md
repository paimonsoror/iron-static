# V1 Visual pass - agent task file

Changelog: 2026-11-08 v1.0. Milestone goal and exit criteria: `docs/ROADMAP.md` section 3 (V1). 22 tasks plus one explicit user gate. Requires M2 complete (HUD, upgrade panel, results overlay exist). Visual authority: `docs/design/10_art_bible.md` (read it fully before any V1 task; every task cites its sections). Same rules, conventions and shared contracts as `docs/tasks/M1.md` and `docs/tasks/M2.md` (read their "Rules" sections first).

## Rules specific to V1

- **View-only.** No file under `src/sim/`, `src/meta/`, `src/save/` or `data/*.csv` changes, and no sim API gains a method for the view's sake. Every task's acceptance includes: `git diff --stat -- src/sim src/meta src/save data` is empty, and `tests/sim/test_replay.gd` golden constants are unchanged. The view reads the world and the event ring only (`SimEventKind`: `SHOT_FIRED`, `ENEMY_HIT`, `ENEMY_KILLED`, `CINDER_HIT`, `BAND_CHANGED`, `BOSS_SPAWNED`, `RUN_ENDED`, `WAVE_STARTED`, `ENEMY_SPAWNED`). New view code lives in `src/view/` (battlefield) and `src/ui/` (HUD), new art under `assets/art/`, new shaders under `assets/shaders/`.
- **Tests and lint stay green** for every task: `tools\lint.ps1` clean, `tools\test.ps1` passes with tests > 0 (V1 adds pure-math/unit tests for every non-trivial view helper; shaders and scenes are verified by screenshots).
- **Screenshot acceptance.** Every visual task attaches emulator screenshots (CLAUDE.md DoD item 4: debug APK installs and launches on `tower_phone`, `tools\smoke_android.ps1` passes). Screenshots are saved under `docs/playtests/v1/<task_id>_<name>.png` and listed in the commit message. The agent states in the report what each screenshot shows; the user judges taste at the gate and at V1 exit. Agents also run the objective pixel checks named in the task (`tools\art_check.ps1`, `ImagePath` checks of `smoke_android.ps1`).
- **No gold plating.** Art is judged against the art bible's silhouette, size and palette rules, not against realism. A task is done when its acceptance is met; polish requests come from the user at the gate.
- **Art authoring rules** are `10_art_bible.md` section 4.4 plus `docs/art/svg_support.md` (written by V1-01, overrides the allowlist). Files: `assets/art/src/<slot>.svg`; slot table `assets/art/slots.csv`; FX and UI sheets as in the art bible. Hex values from art bible section 3.2 only.
- **IP guardrails** (art bible section 11, CLAUDE.md): checked in every art task's acceptance by `tools\art_lint.ps1` (banned-string grep over ids/comments/filenames) and by the reviewer's silhouette checklist.
- **Quality tiers**: every effect that has a cost obeys `VisualQuality` (V1-03). Default tier is HIGH on the emulator; V1-20 decides whether the default must drop to MID.
- Implementation choices not in the art bible are marked **(impl)** in the commit message so the main agent can fold them into the bible or `09_open_questions.md`.
- One agent per module directory at a time. Shared files owned by one task: `project.godot` (V1-03 only, for any settings), `src/view/view_math.gd` (V1-09), `src/view/battle_view.gd` (V1-09 first, then V1-10/11/12/13/14/15 in that dependency order, each adding one line of wiring), `tools/lint.ps1` (V1-02), `src/ui/theme_builder.gd` (V1-16, then V1-17/18 extend through the style API V1-16 defines).
